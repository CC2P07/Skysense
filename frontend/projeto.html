01 / SOBRE O PROJETO

Conheça o Skysense

O SkySense é um projeto acadêmico que propõe o desenvolvimento de uma estação meteorológica baseada na placa ESP32. O sistema utiliza sensores para coletar informações ambientais e disponibilizá-las em um dashboard acessível pelo navegador.

Coleta de dados

Captura de informações ambientais por meio dos sensores conectados à ESP32.

Visualização

Organização das leituras em cartões, indicadores e gráficos.

Tecnologia IoT

Utilização de conectividade para facilitar o acesso às informações da estação.

Objetivo do projeto

Desenvolver um modelo experimental de estação meteorológica com a utilização da placa ESP32, capaz de realizar o monitoramento de diferentes condições ambientais, encaminhar os dados obtidos para uma API programada em Python, armazenar essas informações em um banco de dados e apresentá-las em uma plataforma web por meio de um dashboard.

As estações meteorológicas convencionais possuem custos elevados, o que dificulta sua instalação e amplia sua disponibilidade limitada. Diante disso, este projeto propõe desenvolver uma alternativa econômica, utilizando componentes acessíveis e os conhecimentos adquiridos durante o semestre, capaz de coletar, armazenar e apresentar informações ambientais de maneira prática. Sua importância está na aplicação dos conteúdos de Programação em Python, Sistemas Embarcados, Circuitos Digitais e Engenharia de Software, além de facilitar o acesso a dados que incentivem a conscientização ambiental.

02 / COMPONENTES

ESP32

O ESP32, desenvolvido pela empresa Espressif, é um microcontrolador de baixo custo que possui Wi-Fi e Bluetooth integrados, processador de dois núcleos, entradas e saídas digitais (GPIOs) e conversores analógico-digitais. Essas funcionalidades permitem conectar sensores, coletar informações e transmitir dados pela internet, tornando-o bastante utilizado em projetos de IoT. Sua programação pode ser realizada por meio de ferramentas como Arduino IDE e MicroPython, uma versão simplificada da linguagem Python para microcontroladores. É importante destacar que as entradas analógicas do ADC2 apresentam limitações quando o Wi-Fi está ativado. Por isso, recomenda-se utilizar os pinos 34 e 35, pertencentes ao ADC1, para conectar os sensores analógicos.

API e bancos de dados

A API funciona como uma ponte de comunicação entre diferentes sistemas. Neste projeto, desenvolvida em Python com o auxílio do FastAPI, ela recebe os dados enviados pelo ESP32 via HTTP, realiza o armazenamento em um banco de dados relacional e disponibiliza as informações para consulta no dashboard.

Dashboard

O dashboard é uma interface que organiza as principais informações de um sistema em uma única tela, facilitando o acompanhamento dos dados. No projeto SkySense, ele apresenta cartões informativos (cards) com as medições atuais de cada variável e gráficos que permitem visualizar o histórico e as alterações dos valores ao longo do tempo. Seu desenvolvimento utiliza HTML, CSS e JavaScript, com o auxílio da biblioteca Chart.js para a criação dos gráficos.

03 / Metodologia

Etapas do trabalho

O trabalho é uma pesquisa aplicada, que combina pesquisa bibliográfica (livros, artigos e folhas de dados dos sensores) com o desenvolvimento de um protótipo. Ele foi dividido em cinco etapas:

Etapa 01

Efetuar a coleta de informações ambientais, incluindo temperatura, umidade, pressão atmosférica, qualidade do ar e luminosidade, utilizando a placa ESP32 em conjunto com os sensores DHT22, BMP280, MQ-135 e LDR.

Etapa 02

Realizar a transmissão dos dados obtidos por meio de conexão Wi-Fi para uma API desenvolvida na linguagem Python.

Etapa 03

Armazenar as informações coletadas em uma estrutura de banco de dados, permitindo seu registro e consulta posterior.

Etapa 04

Desenvolver um painel de monitoramento na web para apresentar as medições mais recentes e os registros anteriores, utilizando cartões informativos e gráficos para facilitar a interpretação dos dados.

Etapa 05

Elaborar a documentação técnica do projeto, descrevendo as etapas de desenvolvimento e seguindo as diretrizes estabelecidas pelas normas da ABNT.

Arquitetura do sistema

O funcionamento do sistema ocorre por meio de um fluxo de informações entre os sensores, a ESP32, a API em Python, o banco de dados e o dashboard. A placa coleta as medições e as envia em formato JSON por meio de requisições HTTP POST. A API recebe e armazena os registros, enquanto o dashboard utiliza requisições HTTP GET para consultar e exibir os dados. Essa comunicação foi escolhida por sua simplicidade de implementação e integração entre os componentes.

Firmware do ESP32

O firmware é desenvolvido em MicroPython (Apêndice B) e controla a coleta e o envio das informações. A cada 60 segundos, o ESP32 realiza a conexão Wi-Fi, coleta os dados dos sensores e os encaminha à API em formato JSON. Caso ocorra alguma falha na leitura, o valor correspondente é enviado sem preenchimento. A luminosidade é apresentada em porcentagem, enquanto a qualidade do ar utiliza o valor obtido diretamente pela entrada analógica.

API em Python

A API é escrita com FastAPI (Apêndice C) e tem três endpoints. O FastAPI confere automaticamente se os campos recebidos têm o tipo esperado

Método Rota Função Requisitos
POST /leituras Recebe o JSON do ESP32 e grava na tabela RF02 e RF03
GET /leituras/ultima Devolve a leitura mais recente (usada no cards) RF04
GET /leituras?limite=50 Devolve as últimas leituras (usadas nos gráficos) RF04

Dashboard

O dashboard, é composto por dois elementos principais: cartões (cards) que exibem os valores atuais de temperatura, umidade, pressão, qualidade do ar e luminosidade; e gráficos que permitem acompanhar o histórico das medições e selecionar as variáveis desejadas. A página consulta a API periodicamente para manter as informações atualizadas, sem necessidade de recarregamento.

Esquema de ligação dos sensores ao ESP32:

Pinagem do ESP32:

Sensor Pino do ESP32 Observação
BMP280 GPIO 21 (SDA) e GPIO 22 (SCL) Barramento I²C, alimentado com 3,3 V
DHT22 GPIO 4 Resistor pull-up de 4,7 kΩ no sinal
MQ-135 GPIO 34 (ADC1) Módulo alimentado com 5 V; saída reduzida por divisor de 10 kΩ e 20 kΩ
LDR GPIO 35 (ADC1) LDR em divisor de tensão com resistor de 10 kΩ

O módulo MQ-135 opera com alimentação de 5 V, enquanto os pinos do ESP32 aceitam tensão de até 3,3 V. Por esse motivo, utiliza-se um divisor de tensão para adequar o sinal antes de conectá-lo à placa. Além disso, os sensores analógicos são ligados aos pinos do ADC1, evitando interferências no funcionamento durante a conexão Wi-Fi.

Rede e servidor

O ESP32 opera na faixa de 2,4 GHz do Wi-Fi, então a rede usada precisa oferecer essa faixa. A decisão da equipe é rodar tudo em um computador ligado à mesma rede: a API, o PostgreSQL e os arquivos do dashboard. O ESP32 envia os dados para o endereço IP desse computador, informado no código do firmware.

Arquitetura do banco de dados

O banco de dados utiliza uma única tabela, denominada leituras, responsável por armazenar cada medição realizada. O campo id funciona como identificador exclusivo de cada registro, enquanto o campo data_hora recebe automaticamente a data e o horário da inserção por meio da função now(). As colunas referentes aos sensores permitem valores nulos (NULL), caso ocorra alguma falha na coleta. O dicionário de dados apresenta a descrição das variáveis utilizadas na tabela, e o código SQL está disponível no Apêndice A.

Dicionário de dados da tabela leituras:

Campo Tipo Unidade Descrição

data_hora TIMESTAMP — Data e hora da gravação (automática)
temperatura REAL °C Temperatura do ar (DHT22)
umidade REAL % Umidade relativa do ar (DHT22)
pressao REAL hPa Pressão atmosférica (BMP280)
qualidade_ar INTEGER 0 a 4095 Valor lido no ADC (MQ-135); índice relativo
